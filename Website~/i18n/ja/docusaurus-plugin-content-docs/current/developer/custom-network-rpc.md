# カスタムネットワーク RPC

ベルの音やアニメーションのトリガーなど、一時的なイベントに TSMP RPC を使用します。ドアの `isOpen` や現在のゲーム段階などの持続する値は `[TransSync]` フィールドに保存すると、フレーム損失後に定期的な状態更新で復元できます。

TSMP RPC はメソッド呼び出しを自動的に挿入しません。 `SendTransRPC(methodName, target)` から `TSMPNetworkBehaviour` に電話します。

## 最小限の RPC コンポーネント

```csharp
using K13A.TSMP.Udon;
using UnityEngine;

public class BellSync : TSMPNetworkBehaviour
{
    public AudioSource bell;

    public override void Interact()
    {
        SendTransRPC(nameof(Ring), RPCTarget.All);
    }

    public void Ring()
    {
        if (bell != null)
        {
            bell.Play();
        }
    }
}
```

## `SendTransRPC()`

```csharp
public bool SendTransRPC(string methodName, RPCTarget target)
```

| パラメータ | 意味 |
| --- | --- |
| `methodName` | ターゲットの動作に対して実行するパブリック メソッド名。可能な場合は `nameof(Method)` を使用してください。 |
| `target` | `Local`、`Remote`、または `All`。 |

`Remote` と `All` の `true` は、ローカルのエンコーダがイベントをキューに受け付けたことを示します。他のクライアントでの受信や実行の確認ではありません。エンコーダの未割り当て、キュー満杯、現在の payload 予算に入らないイベントなどでは `false` が返る場合があります。

`All` はリモート用キューへの登録を試みる前にローカルメソッドを実行します。`false` が返ってもローカルの処理は実行済みの場合があり、`All` 全体を再試行するとローカル処理を重複実行する可能性があります。

## `RPCTarget`

| ターゲット | 送信者の動作 | 受信機の動作 |
| --- | --- | --- |
| `Local` | メソッドをすぐに実行します。 | 何もキューに入れられていません。 |
| `Remote` | ローカルでは実行されません。 | デコードされた受信者のキューメソッド。 |
| `All` | すぐに実行されます。 | デコードされた受信者のキューメソッドも使用します。 |

送信者と受信者が OBS または別のキャプチャ パスを介してループバックされる場合、`All` はすぐに 1 回実行され、キャプチャ遅延後に再度実行される可能性があります。

## 信頼性とリピートフレーム

エンコーダはキューの各イベントを `transRpcRepeatFrames` 回の成功した出力に含めます。既定値は 4 回です。受信側は容量制限のある重複抑制キャッシュ内で、正のイベント ID の再実行を防ぎます。受信確認はないため、映像の欠落が全コピーを覆うとイベントは永久に失われる場合があります。定期的な状態更新は RPC を再生成しません。

反復回数を増やすと個別のフレーム損失には役立つ場合がありますが、FIFO キューの先頭イベントが長く残り、後続イベントも遅れます。先にキューの増加と最初の適用までの遅延を確認してください。送信側の現在値に復元すべき情報には状態フィールドを使います。状態更新も途中の全遷移を保存するものではありません。

## メソッドの制限

- メソッドは受信側 `TSMPNetworkBehaviour` に存在する必要があります。
- Udon セーフ パスのために、RPC メソッドをパブリックにして引数なしで維持します。
- イベントにパラメータが必要な場合は、`[TransSync]` フィールドにデータを入力します。
- フレームの繰り返しが可能な場合、副作用を冪等に保ちます。

## デバッグチェックリスト

| 症状 | チェック |
| --- | --- |
| ローカルアクションは機能するが、遅延アクションは機能しない | エンコーダ `queuedRpcCount`、`rpcMessageCount`、およびデコーダ `lastRpcCallCount`。 |
| イベントが欠落しました | キューへの受付、payload の保留、映像の欠落を確認します。全コピーが失われる場合があるため、持続する値には状態フィールドを使います。 |
| 負荷時にイベントが遅れます | 反復回数を増やす前にキューの増加と現在の反復回数を確認します。 |
| 間違ったオブジェクトがイベントを受信しました | `Apply Setup` を実行し、`networkId` 値が一意であることを確認します。 |
