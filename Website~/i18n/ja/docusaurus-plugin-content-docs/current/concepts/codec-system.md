# コーデックの選択

コーデックは、TSMP バイトをピクセルとして表現する方法を制御します。

プロトコルはヘッダーとペイロードの意味を定義します。コーデックは、テクスチャ パスを通じてこれらのバイトを運ぶために使用される視覚的表現を定義します。

## Luma4

Luma4 は、TSMP に含まれるデフォルトのコーデックです。これはサンプル プレハブで使用されるベースライン パスであり、セットアップとトラブルシューティングで推奨される最初の選択肢です。

次の場合に Luma4 を使用します。

- TSMP を初めて設定します。
- キャプチャ設定を変更する前に、安定した参照パスが必要です。
- シーンのセットアップまたはトランスポート パスに問題があるかどうかをデバッグしています。
- サンプル プレハブとデフォルトのセットアップがシーンに正確に一致するようにしたい。

## Luma4 セットアップ中

`TSMPSetup` は、[コーデック] タブに Luma4 ハンドラーを示します。表示されない場合:

1. Luma4 パッケージがインストールされていることを確認します。
2. 「`Refresh Codecs`」をクリックします。
3. コーデック プレハブとカタログ アセットが存在することを確認します。
4. 「`Apply Setup`」をクリックします。

送信者と受信者は互換性のある Luma4 設定を使用する必要があります。コーデックの不一致によっても可視ピクセルが生成される可能性はありますが、デコーダが間違ったブロックまたは間違ったバイト値を読み取る可能性があります。

## キャプチャの品質は重要です

コーデックは、トランスポート パスに残ったもののみをデコードできます。避ける：

- エンコードされた領域のバイリニアまたはトリリニア スケーリング。
- 色補正またはトーン マッピング。
- TSMP 領域でのビデオ圧縮。
- OBS ピクセル値を変更するフィルター。
- ヘッダーまたはペイロード ブロックを削除するトリミング。
- TSMP 出力を描画するカメラ効果。

デコーダが CRC の不一致を報告した場合は、ネットワーク コンポーネントを変更する前にトランスポートをデバッグします。

## 容量と品質のトレードオフ

テクスチャ解像度が高くなるとペイロード容量が増えますが、レンダリング、キャプチャ、デコード作業のコストも増加します。

サンプルのデフォルトから始めます。デバッグ キャンバスでペイロードの使用量が容量に近づいていることが示され、不要な同期データがすでに削減されている場合にのみ、解像度を上げます。
