---
title: ヒューマノイド受信モデルの GPU スキニング
---

ワールド内に**演者の姿を描画する**ための方法です。送信側は通常の `TSMPNetworkHumanoidPoseSync` を使い、受信側は[シェーダーチャンネル](./shader-receive.md)からベイク済みのメッシュを変形します。シーンのボーン Transform やコライダー、ボーンに付けた小物は動きません。他のコンポーネントでボーン位置が必要なら CPU 受信も残してください。

## 受信モデルをベイクする

1. 受信側デコーダーの **Shader Channel** を有効にします。先にデコーダーとコーデックで正常なフレームを受信できる状態にしてください。
2. Edit Mode で受信モデルの有効な Humanoid Animator を基準姿勢にし、その子の SkinnedMeshRenderer を選びます。モデルは **Read/Write Enabled** でボーン Transform が公開され、ウェイトは頂点あたり 4 個以下である必要があります。ウェイトを持つボーンは Hips またはその子孫に限ります。Animator とその祖先、Animator と Hips の間の Transform には正の均一スケールを使用してください。
3. **TSMP → Bake Humanoid GPU Skin** を開きます。デコーダーの Inspector にある **Bake Humanoid GPU Skin** から開くと、そのデコーダーが選択されます。受信側の Animator と Source Renderer を指定します。送信側のポーズコンポーネントとデコーダーを指定すると Network ID とチャンネルが読み込まれます。送信側が別のプロジェクトにある場合など、参照できない側は空欄のまま値を直接入力します。ID とチャンネルはアセットに焼き込まれるため、変更後は再度ベイクしてください。 **Motion Margin** はメッシュの各方向へ加える移動範囲（Animator ローカル単位）です。World ルートモーションでは受信モデルをステージ付近に配置してください。カリングには変形後の頂点ではなく、この固定範囲が使われます。
4. **Bake GPU Skin** を押して Assets 内の新規アセットに保存し、シーンを保存します。**Last Bake** で生成された GPU レンダラーとベイク済みメッシュを確認できます。すべてを GPU で描画する場合は元のレンダラーが無効になり、混在させる場合は残した三角形のみ元のレンダラーで描画します。インポートしたモデルアセットは変更されません。複数メッシュの場合はそれぞれベイクしてください。生成オブジェクトのローカル Transform は変更せず、静的バッチングの対象にも含めないでください。
5. 送信側のアニメーションを再生します。Hips の Local・World モーションに対応します。受信用ポーズコンポーネントは不要です。他の用途がなければ CPU 側の受信を無効にするか、受信モードを **None** にしてください。

生成されるアセットにはメッシュ、リグ情報、パレット、マテリアルが入っています。標準の Built-in 用不透明シェーダーはアルベドテクスチャ、タイリング・オフセット、色を引き継ぎますが、元のシェーダー全体は変換しません。ボーン階層・ウェイト・基準姿勢を変更した場合は再ベイクしてください。ベイク直後に Edit → Undo を実行すると、シーンオブジェクトと元のレンダラーの割り当てが復元されます。生成されたアセットは Project に残ります。

## 反映される動き

2 つの GPU パスが現在の v4 `humanoid.pose` を読み、ボーン行列を生成します。マテリアルはこの行列で頂点位置・法線・接線を変形します。ボーンごとの Udon Transform 書き込みやスキニング結果の readback はありません。デコーダー自体の検証と readback は従来どおりです。ベイクした各メッシュにつき、描画フレームごとに 2 枚のパレットを更新します。特定のフレーム時間の短縮を保証するものではありません。

選択されたヒューマノイドボーンの回転は補間せずに適用します。未選択のボーンと補助ボーンはベイク時のローカル姿勢を保ち、親に追従します。SendOnChange でフィールド全体が省略されても直前の値を保ちます。チャンネルやフィールドがない場合や未対応の形式では基準姿勢を表示します。VRChat プレイヤープールの別形式のパケット、揺れものの物理演算、BlendShape、CPU 受信補間には対応していません。

## 送信するポーズからボーンを除外する

送信側の `TSMPNetworkHumanoidPoseSync` で、Hips より下のボーンを **Excluded Send Bone Roots** に指定します。指定したボーンとその子孫は送信されません。頭の動きを残して髪だけを除外するなら、Head ではなく HairRoot を選びます。物理や GPU スキニングは不要です。受信側に同じリストを設定する必要はなく、受信したボーンの適用対象は従来どおりリグマップで選びます。マッピング済みの回転を 1 個除外するとポーズあたり 6 バイト減ります。未マッピングの補助ボーンは元から送信されません。

**描画は別の設定です。** メッシュの一部をアニメーション・制約・物理で動かす場合、ベイク時に **Keep on Skinned Renderer** に対応する**受信リグのボーン**を指定します。その配下にウェイトを持つ頂点に接する三角形は、ウェイト・マテリアルスロット・BlendShape フレームとともに元のレンダラーに残ります。空欄なら従来の GPU 専用描画になります。すべて元のレンダラーに残す装飾メッシュはベイク不要です。

ローカルのボーンが送信ポーズに追従する必要がある場合は、送信 ID にバインドした **Discrete** の CPU 受信コンポーネントで実際の祖先と境界の頂点に影響する非除外ボーンを動かします。CPU とシェーダーの更新タイミングは一致するとは限りません。分割を変更するには元のメッシュに戻し、生成したレンダラーを削除してから再ベイクします。送信リストの変更だけなら再ベイクは不要です。実行時に親子関係を変えた場合は `InvalidateReceiveRig()` を呼んでください。

メッシュを分割すると、各レンダラーには三角形が残ったマテリアルスロットだけが元の順序で残ります。元の最終サブメッシュに重ねて描画していた追加マテリアルは、その三角形が残る側だけに適用されます。スロット番号でマテリアルを切り替えるアニメーションやスクリプトは、ベイク後の番号を確認してください。再ベイク前に元のメッシュとマテリアルのリストを両方復元してください。既存のベイクは自動更新されません。

## カスタムマテリアル

マテリアルの 2D プロパティ `_TSMPSkinPalette` に生成済みのスキンパレットを指定し、バッチングを無効にします。影を含め、メッシュを描画するすべてのパスに変形を適用してください。**ベイクしたコピー**の UV3 と UV4 にはそれぞれボーンインデックスとウェイトが入っています。クリップ空間へ変換する前に次の関数を呼びます。

```hlsl
#pragma target 3.5
#include "Packages/com.kibalab.tsmp.core/Shaders/TSMPSkinning.cginc"

void vert(inout appdata_full v)
{
    float3 p = v.vertex.xyz;
    TSMPSkinVertex(p, v.normal, v.tangent, v.texcoord2, v.texcoord3);
    v.vertex.xyz = p;
}
```
