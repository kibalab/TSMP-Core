## Reproduction

Download and hash-check the ZIPs in the inventory, extract independently for each environment and point isolated project manifests at those folders. Use the existing harness from the release-preparation main revision e8d04fb:

```powershell
./Validation~/ContinuousFrames/Run-Validation.ps1 -ProjectPath F:/Unity/TSMP/Validation-Results/release-1.0.0/NoSDK -ResultsDirectory F:/Unity/TSMP/Validation-Results/release-1.0.0/results/player -Mode Player -Filter 'prediction-regression,overlap-regression'
./Validation~/ContinuousFrames/Run-Validation.ps1 -ProjectPath F:/Unity/TSMP/Validation-Results/release-1.0.0/VRC -ResultsDirectory F:/Unity/TSMP/Validation-Results/release-1.0.0/results/udon -Mode Udon -Filter 'prediction-regression,overlap-regression'
```

The SDK follow-up invocations used the same command with results directories udon-reopen and udon-confirm. Keep separate result folders when repeating runs. The harness uses a real graphics device, not -nographics, and Udon mode explicitly compiles all programs for the client target before running the SDK VM.

## Limits

No new CPU/GPU benchmark, live VRChat client, SDK world bundle, OBS/Spout/MediaMTX path, populated avatar scene, Quest/mobile, IL2CPP/stripping, other graphics API or long-duration soak was run for this stable promotion. Existing shader warnings and the earlier legacy Linear harness limitation remain. Publication workflow success is not substituted for runtime validation.
